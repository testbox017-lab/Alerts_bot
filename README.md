# Alerts_bot

**Русский** · [English](README.en.md)

Telegram-бот для себя, семьи или группы:

- 🚨 **воздушные тревоги** по выбранным областям (до 5, например где живут родные; можно сузить до районов/громад) — источник: API приложения «Повітряна тривога» ([ukrainealarm.com](https://api.ukrainealarm.com)) или [alerts.in.ua](https://alerts.in.ua);
- 💡 **графики отключений света** по вашей очереди с напоминанием за N минут до отключения и включения. Графики берутся из открытых сборщиков [OE_OUTAGE_DATA](https://github.com/yaroslav2901/OE_OUTAGE_DATA) и [outage-data-ua](https://github.com/Baskerville42/outage-data-ua), для Винницкой области — [gpv-voe-vinnytsia](https://github.com/vn-progr/gpv-voe-vinnytsia), для Николаевской — официальный API [off.energy.mk.ua](https://off.energy.mk.ua), для Сумской, Волынской и Кировоградской — сборщик [Koly Ye](https://github.com/vkardin/koly). Для Херсонской и Черновицкой областей открытых источников пока нет.

Каждый чат (личка или группа) настраивает свои области (до 5) и очередь кнопками через `/start`. Очередей можно отметить до 5 (например, дом и дача): график и напоминания приходят по каждой отдельно.

## Поддерживаемые графики света

Київ, Київщина, Дніпропетровщина, Одещина (ДТЕК), Черкаська, Чернігівська, Харківська, Хмельницька, Львівська, Полтавська, Івано-Франківська, Рівненська, Тернопільська, Закарпатська, Запорізька, Житомирська области.

Для остальных областей тревоги работают, а график можно вводить вручную: `/svet 06:00-09:00 15-18`.

## Кнопки и команды

После `/start` внизу экрана появляется меню: **💡 Графік світла**, **🚨 Тривоги зараз**, **⚙️ Налаштування** (область, очередь, напоминания, районы — кнопками), **❓ Допомога**. Те же действия доступны командами:

| Команда | Что делает |
|---|---|
| `/start` | выбрать области и очередь |
| `/settings` | текущие настройки, кнопки «изменить» |
| `/status` | активные тревоги сейчас |
| `/raion Ніжинський, Бахмацька` | тревоги только на всю область + эти районы/громады; `/raion clear` — вся область |
| `/svet` | график на сегодня и завтра (кнопка «📋 Всі черги» — все очереди поставщика) |
| `/svet 06:00-09:00 15-18` | ручная правка на сегодня (`/svet zavtra …` — на завтра, `/svet -` — без отключений, `/svet clear` — убрать правки) |
| `/remind 30` | за сколько минут предупреждать (`0` — выключить) |
| `/stop` | отписаться |

В группах настройки меняют только админы. Команды бот видит всегда, а чтобы работали кнопки меню, сделайте бота админом группы (или выключите ему privacy mode в @BotFather → `/setprivacy` → Disable).

## Запуск на сервере (Ubuntu + Docker)

Один раз на сервере:

```bash
# Docker, если ещё нет
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER   # перелогиниться после этого

mkdir -p ~/alerts_bot/data && cd ~/alerts_bot
nano .env   # вставить содержимое .env.example и заполнить токены
```

- `BOT_TOKEN` — у [@BotFather](https://t.me/BotFather) (`/newbot`);
- Тревоги работают **без ключа**: по умолчанию бот берёт данные из публичного зеркала API «Повітряна тривога» (siren.pp.ua). Для надёжности можно добавить свои ключи. Бот идёт по цепочке alerts.in.ua → ukrainealarm.com → зеркало (источники без ключа пропускаются): после 3 ошибок подряд переходит на следующий, раз в 5 минут пробует вернуться на более приоритетный.
  - `UKRAINEALARM_TOKEN` — официальный API «Повітряна тривога», форма запроса ключа на [api.ukrainealarm.com](https://api.ukrainealarm.com);
  - `ALERTS_TOKEN` — [devs.alerts.in.ua](https://devs.alerts.in.ua).
  Поставить источник первым в цепочке: `ALERTS_SOURCE=ukrainealarm|alertsinua|mirror`. После изменения `.env`: `cd ~/alerts_bot && docker compose up -d --force-recreate`.
  Какой источник быстрее: `ALERTS_COMPARE=1` (нужны оба ключа). Бот раз в минуту (чаще ключ ukrainealarm не пускает) опрашивает alerts.in.ua и ukrainealarm одновременно и пишет в `data/compare.jsonl`, кто раньше сообщил о тревоге и відбої и на сколько секунд. Рассылка при этом не меняется. Отчёт — команда `/compare`.

Дальше всё делает GitHub Actions.

## Автодеплой

При каждом push в `main` workflow `.github/workflows/deploy.yml`:

1. гоняет тесты;
2. собирает Docker-образ и публикует его в `ghcr.io/testbox017-lab/alerts_bot`;
3. по SSH копирует `docker-compose.yml` в `~/alerts_bot` на сервер и делает `docker compose pull && docker compose up -d`.

Нужные секреты (GitHub → репозиторий → Settings → Secrets and variables → Actions → New repository secret):

| Секрет | Значение |
|---|---|
| `SSH_HOST` | IP или домен сервера |
| `SSH_USER` | пользователь на сервере (в группе `docker`) |
| `SSH_KEY` | приватный SSH-ключ (весь текст, вместе с `-----BEGIN…`) |
| `SSH_PORT` | необязательно, по умолчанию 22 |

Отдельный ключ для деплоя:

```bash
# на своём компьютере
ssh-keygen -t ed25519 -f deploy_key -N "" -C "github-deploy"
ssh-copy-id -i deploy_key.pub user@server
# содержимое deploy_key -> секрет SSH_KEY
```

Пока секреты не заданы, деплой просто пропускается с предупреждением.

## Ручной запуск / разработка

```bash
cp .env.example .env   # заполнить
docker compose up -d --build
docker compose logs -f
```

Без Docker: `pip install -r requirements-dev.txt && python -m pytest && python -m bot`.

Данные (подписчики, кэш графиков) лежат в SQLite `data/bot.db`.
