# CLAUDE.md

Памятка для Claude Code (и для себя) о проекте **Alerts_bot**. Владелец — Dmitry, общаемся по-русски.

## Что это

Telegram-бот **@alerts_svitlo_bot** для себя, семьи и групп (родные живут в разных областях):

- 🚨 воздушные тревоги по выбранным областям (до 5 на чат), с фильтром по районам/громадам (`/raion`);
- 💡 графики отключений света по очереди (до 5 очередей на чат) с напоминанием за N минут до отключения и включения;
- работает и в личке, и в группах (в группах настройки меняют только админы).

Каждый чат хранит свои настройки в SQLite. График света привязан к **главной** (первой выбранной) области.
Тексты для пользователей — на украинском, комментарии в коде и README — на русском.

## Структура

```
bot/
  __main__.py     точка входа: python -m bot
  main.py         aiogram 3: команды, кнопки, циклы alerts_loop / power_loop / reminder_loop
  config.py       все настройки из переменных окружения (.env)
  alerts.py       цепочка источников тревог, fallback, фильтры по области/району, форматирование
  ukrainealarm.py клиент API ukrainealarm (и зеркала siren.pp.ua), конвертация в формат alerts.in.ua
  compare.py      режим ALERTS_COMPARE: кто из источников раньше сообщает о тревоге, /compare
  power.py        парсеры графиков (GPV/OE, svitlo, Миколаїв, Koly Ye, Світлячок), интервалы, напоминания, «устарел ли график»
  regions.py      список областей и карта «поставщик графика → URL источника»
  sender.py       параллельная рассылка с ограничением скорости и обработкой 429
  db.py           SQLite: subs, overrides (ручные графики /svet), sched (кэш), settings, sent
tests/            pytest, без сети
tools/loadtest.py нагрузочный тест с фейковым Bot API на 127.0.0.1
Dockerfile, docker-compose.yml, .github/workflows/deploy.yml
README.md (рус.), README.en.md (англ.) — пользовательская документация, держать в актуальном виде
```

## Как запускать

```bash
pip install -r requirements-dev.txt
python -m pytest -q          # 39 тестов, ~1 с, сеть не нужна
cp .env.example .env         # заполнить BOT_TOKEN и ключи
python -m bot                # локально
docker compose up -d --build # в Docker
python -m tools.loadtest --users 1000 --latency 50       # нагрузка: тревога на 1000 чатов
python -m tools.loadtest --users 1000 --scenario remind  # нагрузка: напоминания
```

Python 3.12, aiogram 3.13, aiohttp. Часовой пояс — Europe/Kyiv (`config.TZ`).

Из облачной песочницы Claude не доступны Telegram и api.alerts.in.ua (а off.energy.mk.ua режет не-браузерный User-Agent), поэтому живые проверки делаются на сервере.

### Переменные окружения (только имена, значения — в `.env` на сервере)

`BOT_TOKEN`, `ALERTS_TOKEN` (alerts.in.ua), `UKRAINEALARM_TOKEN`, `ALERTS_SOURCE`, `ADMIN_IDS`,
`ALERTS_POLL_SECONDS`, `UKRAINEALARM_POLL_SECONDS`, `ALERTS_COMPARE`, `ALERTS_COMPARE_SECONDS`,
`POWER_POLL_SECONDS`, `POWER_UNREACHABLE_MIN`, `POWER_STALE_HOURS`, `DEFAULT_REMIND`, `POSSIBLE_AS_OFF`,
`SEND_RATE`, `SEND_CONCURRENCY`, `SEND_ATTEMPTS`, `DB_PATH`. Описание — в `bot/config.py` и `.env.example`.

**После изменения `.env` на сервере:** `cd ~/alerts_bot && docker compose up -d --force-recreate` (простой `restart` не перечитывает `.env`).

## Серверы и деплой

- **OVH** — рабочий сервер. Бот в `/root/alerts_bot` (`docker-compose.yml`, `.env`, `data/bot.db`), там же weather-bot. ufw + fail2ban, вход по SSH только по ключу.
- **Hetzner** — только наблюдатель: Monitor-bot (следит за обоими серверами). Старая копия alerts_bot на Hetzner остановлена 2026-11-24 (папка `~/alerts_bot` осталась на диске). **Не запускать её снова** — два бота с одним токеном конфликтуют (getUpdates).
- IP-адреса и ключи в репозиторий не кладём (репозиторий публичный).
- Доступ к серверам — с ПК Dmitry (Windows, папка `D:\Program\prg_py\Alerts_bot`, ключ `~/.ssh/id_ed25519`). На Windows следить за CRLF и кавычками в командах через ssh.

**Автодеплой:** push в `main` → GitHub Actions (`deploy.yml`): pytest → сборка образа `ghcr.io/testbox017-lab/alerts_bot` → по SSH копирует `docker-compose.yml` в `~/alerts_bot`, `docker compose pull && up -d`. Секреты репозитория: `SSH_HOST`, `SSH_USER`, `SSH_KEY` (`SSH_PORT` по желанию). Без секретов деплой пропускается с предупреждением. На PR выполняются только тесты и сборка.

**Порядок работы:** ветка → PR → Dmitry проверяет и пишет «мержи» → merge в `main` → автодеплой. Не пушить в `main` напрямую.

## Принятые решения и почему

**Источники тревог.** Цепочка alerts.in.ua → ukrainealarm → siren.pp.ua (зеркало без ключа, всегда последнее); источник без ключа пропускается; после 3 ошибок подряд — следующий.
- Сравнение 2026-11-24/25 (26 ч, тики по 60 с): начала тревог по областям 116 (99 одновременно, ukrainealarm раньше на тик в 9 случаях, alerts.in.ua раньше — ни разу); отбои 117 (100 одновременно, alerts.in.ua раньше в 15). То есть источники почти одинаковые.
- Ключ ukrainealarm пускает ~1 запрос в минуту (чаще — 429), поэтому с ним опрос раз в 60 с (`UKRAINEALARM_POLL_SECONDS`).
- Пробовали ставить ukrainealarm первым (опрос 60 с) — на практике оповещения казались медленнее (в среднем ~30 с задержки). 2026-11-25 вернули: **alerts.in.ua первым, `ALERTS_POLL_SECONDS=15`**, без `ALERTS_SOURCE` и `ALERTS_COMPARE` в `.env` на сервере.
- Выбор источника кнопкой (`/source`, PR #21) хранится в таблице `settings` и важнее `ALERTS_SOURCE`. Владелец — `ADMIN_IDS` или первый, кто отправил `/source` в личке.
- Ключи в логи не пишутся.

**Графики света.** Только открытые машиночитаемые источники:
- [OE_OUTAGE_DATA](https://github.com/yaroslav2901/OE_OUTAGE_DATA) (12 облэнерго) и [outage-data-ua](https://github.com/Baskerville42/outage-data-ua) (ДТЭК: Киев, Киевщина, Днепропетровщина, Одесщина);
- Винницкая — gpv-voe-vinnytsia; Николаевская — официальный API off.energy.mk.ua (нужен браузерный User-Agent, иначе Cloudflare 403); Сумская, Волынская, Кировоградская — [Koly Ye](https://github.com/vkardin/koly) (`koly:<id>` в `regions.py`; Koly Ye — также запасной кандидат для других областей).
- Черновицкая — [svitlyachok-data](https://github.com/ABovsh/svitlyachok-data) (`svitlyachok:chernivtsi`): сборщик на сервере в Украине каждые 15 мин читает oblenergo.cv.ua (GitHub-раннерам сайт отдаёт 403), 48 получасов на группу 1–12, `checked` обновляется минимум раз в час. Сам сайт из облака/OVH напрямую не парсим.
- Херсонская — источника нет (Херсонобленерго показывает график только в личном кабинете; проверено ещё раз 2026-11-27), только ручной `/svet`. Донецкая, Луганская, Крым — графиков нет.
- Напрямую Черниговоблэнерго подключить нельзя (нет открытого API).
- **Userbot не делаем** (нужен вход по номеру телефона на сервере, лишний риск). Файл `userbot.py` в папке проекта — устаревший, в репозитории его нет.

**Рассылка.** Реальный потолок — лимит Telegram ~30 сообщений/с на бота. Старая последовательная рассылка: 1000 чатов ≈ 54 с при задержке 50 мс и 154 с при 150 мс, и опрос тревог на это время вставал. Сейчас (#22): параллельно, `SEND_RATE=25`/с, при 429 пауза + замедление + повтор; 1000 чатов ≈ 42 с, 5000 ≈ 205 с независимо от задержки, опрос не блокируется.

## Известные проблемы и подводные камни

- ukrainealarm: тревоги по районам вложены в записи громад; псевдо-регионы 564/1293 (города Запорожье/Харьков); тестовый регион 0 — всё это обрабатывается в `ukrainealarm.py`, не ломать.
- Источники графиков иногда отстают или пропадают — для этого есть предупреждения (`POWER_UNREACHABLE_MIN`, `POWER_STALE_HOURS`).
- Кнопки меню в группах работают, только если бот — админ группы или у него выключен privacy mode (@BotFather → `/setprivacy`).
- Данные контейнера в `./data` (uid 1000) — при ручном развёртывании проверить владельца папки.
- На Hetzner лежит остановленная копия бота — не путать серверы.
